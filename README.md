# DARI

## 2026-10 대화형 초안 작성 MVP

현재 개발 대상은 `capacitor-web/`의 **모국어 LLM 대화 → 메타데이터 → 한국어 신청서 초안** 흐름입니다. 사용자 원문과 추출한 사실, 초안 문장별 근거를 함께 내보낼 수 있습니다. Design1의 흰색·검정색 UI와 RTL 언어 배치를 적용합니다.

- 모바일 앱: 가져온 `.litertlm` 모델을 LiteRT-LM으로 기기에서 실행합니다. 모델이 없거나 실행에 실패하면 오류를 표시하며 외부 서버로 자동 전환하지 않습니다.
- 브라우저 개발 미리보기: 개발 컴퓨터의 Ollama를 사용합니다. 휴대폰 온디바이스 성능을 검증하는 경로는 아닙니다.
- 현재 집중 시험 범위: 14.1~14.3. 전체 서식 수집 목록과 조건부 분기도 제공하며, 수집 중/미확인 사항을 구분합니다.
- 결과물: `source`, `metadata`, 한국어 `draft`. 문서 완성도와 모델 생성문 정확도는 서로 다른 항목으로 평가해야 합니다.

실행과 구조는 [대화형 초안 구현 안내](docs/INTAKE_IMPLEMENTATION.md), 기기 모델 준비는 [온디바이스 실행 안내](docs/NATIVE_LLM.md)를 참고하세요.

## 팀원용 로컬 실행 안내

현재 개발 브랜치는 `feat/q14-metadata-intake`입니다. 아래는 각자 컴퓨터에서 웹 화면과 모델을 실행하는 방법입니다. Android Studio, 에뮬레이터, Tailscale은 필요하지 않습니다. 휴대폰 온디바이스 실행이 아니라 컴퓨터의 Ollama로 기능을 테스트합니다.

### 1. 준비 및 코드 받기

Git, Node.js 22 이상(npm 포함), Python 3, [Ollama](https://ollama.com/)를 설치합니다.

```sh
git clone -b feat/q14-metadata-intake https://github.com/woojin0220/2026-TechForImpact-DARI.git
cd 2026-TechForImpact-DARI
```

이미 받은 레포가 있다면 해당 폴더에서 다음을 실행합니다. 작업 중인 변경사항은 먼저 커밋하거나 별도로 보관하세요. 브랜치 전환이나 pull이 실패하면 변경사항을 강제로 지우지 않습니다.

```sh
git fetch origin
git switch feat/q14-metadata-intake
git pull --ff-only
```

### 2. 모델 실행 및 다운로드

Ollama 앱을 실행하거나 터미널에서 아래 명령을 실행하고 켜둡니다. 이미 Ollama가 실행 중이면 중복 실행하지 않습니다.

```sh
ollama serve
```

다른 터미널에서 기본 모델을 내려받습니다. 다운로드는 최초 한 번만 필요합니다.

```sh
ollama pull gemma4:e4b
ollama list
```

### 3. DARI API 서버 실행

레포 최상위 폴더에서 실행하고 터미널을 켜둡니다. Python 표준 라이브러리만 사용하므로 별도의 pip 설치는 필요하지 않습니다.

```sh
python3 local_verification_server.py
```

파일 이름은 검증 서버지만 현재 대화·메타데이터 추출·초안 작성 등의 모델 요청도 처리합니다.

### 4. 웹 화면 실행

새 터미널을 열고 레포 최상위 폴더에서 실행합니다.

```sh
cd capacitor-web
npm ci
npm run dev -- --host 127.0.0.1 --port 5188 --strictPort
```

브라우저에서 **http://127.0.0.1:5188/** 에 접속합니다. 화면은 5188, DARI API는 8765, Ollama는 11434 포트를 사용합니다. `8765`는 화면 주소가 아니므로 브라우저로 직접 열면 GET 관련 오류가 표시될 수 있습니다.

각 터미널은 테스트하는 동안 켜두며 종료할 때는 `Ctrl+C`를 누릅니다. 다음 실행부터는 모델 다운로드와 `npm ci`를 생략할 수 있습니다. 단, 업데이트로 의존성이 바뀌었다면 `npm ci`를 다시 실행합니다. `127.0.0.1`은 각자 자기 컴퓨터를 가리키며 다른 팀원에게 공유하는 접속 주소가 아닙니다.

### 5. 짧은 테스트 진행

1. 첫 화면에서 **Conversation test · English → Korean**을 선택합니다.
2. 영어로 답하거나 **Generate an example**로 현재 질문에 맞는 가상 답변을 생성한 뒤 직접 전송합니다.
3. LLM의 추가 질문에 답합니다. 중간에 끝내려면 **Finish**를 누릅니다.
4. 수집된 정보를 확인한 뒤 한국어 초안을 생성합니다. 모르는 내용이나 말하지 않은 사실이 추가되지 않았는지 확인합니다.
5. 한국어 초안과 자동 생성되는 영어 역번역을 확인하고 문장을 선택해 영어로 수정을 요청합니다. 제안을 확인한 뒤 적용하거나 되돌립니다.
6. 전체 결과 JSON 또는 한국어 초안 TXT를 저장합니다. JSON은 원문·메타데이터·초안 및 수정 이력을 포함하고 TXT는 현재 초안 내용을 저장합니다.

처음부터 다시 테스트하려면 새로고침합니다. 자동 저장과 저장 파일을 통한 작업 복원은 없으므로 필요한 결과는 먼저 내려받으세요. 실제 개인정보 대신 가상 사례를 사용하고, 오류 제보에는 입력 내용·기대한 결과·실제 결과를 함께 남겨주세요.

### 연결 문제와 개발 테스트

- **Failed to fetch**: DARI 서버 터미널을 확인합니다. 별도 서버 주소를 설정하지 않았다면 웹 앱은 같은 컴퓨터의 8765 포트에 연결합니다.
- **모델 오류**: `ollama list`에 `gemma4:e4b`가 있는지, Ollama가 실행 중인지 확인합니다. 첫 요청은 모델 로딩으로 느릴 수 있습니다.
- **포트 사용 중**: 기존 프로세스를 확인합니다. 다른 작업의 서버를 임의로 종료하지 마세요. 웹 포트만 바꾸려면 실행 명령의 `--port 5188`을 사용 가능한 번호로 변경하고 해당 주소로 접속합니다.
- **화면이 이전 버전**: 현재 브랜치와 pull 결과를 확인하고 새로고침합니다.

프런트엔드 검사 명령은 `capacitor-web` 폴더에서 실행합니다.

```sh
npm test
npm run build
```

## 현재 개발 기준: Capacitor 웹 앱

새 기능은 [`capacitor-web/`](capacitor-web/)의 React·TypeScript·Capacitor 앱을 기준으로 개발합니다. 하나의 웹 화면을 Android와 iOS 네이티브 래퍼에서 함께 사용하기 위한 전환입니다. 기존 루트의 Kotlin Android 앱은 ML Kit 온디바이스 번역을 실험한 참고 구현으로 남아 있으며 삭제하지 않았습니다.

Capacitor 앱의 번역은 Android·iOS 기기에서 ML Kit으로 처리합니다. 브라우저 미리보기는 로컬 Ollama로 번역하고, 왜곡 검증도 그 서버를 사용합니다. 자세한 실행 및 전환 절차는 [Capacitor 웹 기반 전환 안내](docs/CAPACITOR_MIGRATION.md)를 확인해 주세요.

## 주요 기능

1. 공식 신청서 문항을 선택 언어로 보여 주고 그 아래 영어를 두며, 같은 언어로 답변 입력
2. Google ML Kit을 이용한 온디바이스 `선택 언어 → 영어 → 한국어` 번역
3. 문항별 원문·영어·한국어 최종본 확인
4. 개인정보 제외본 확인 및 수정
5. Qwen3 4B 또는 Llama 3.2 3B를 이용한 전체 번역본 검증
6. 누락·추가·부정 반전·행위자·시간·인과관계·피해 강도 등의 왜곡 후보 표시

UI에 있는 네 언어는 데모 범위이며 공식 지원 언어로 확정된 것은 아닙니다. 실제 문항 번역도 공인 통역 또는 관련 전문가의 검토가 필요합니다.

## 시스템 구조

```text
Android 앱 또는 에뮬레이터
  ├─ 모국어 문항과 답변 입력
  ├─ ML Kit 온디바이스 번역
  │    └─ 선택 언어 → 영어 → 한국어
  ├─ 영어·한국어 병기본 표시
  └─ 사용자가 확인한 개인정보 제외본 전송
                    │
                    ▼
개발 컴퓨터의 DARI 검증 서버
  └─ Ollama
       ├─ Qwen3 4B
       └─ Llama 3.2 3B
```

기계번역은 Android 기기 안에서 처리됩니다. LLM 검증은 개발 컴퓨터에서 실행되는 Ollama가 담당합니다. 현재 구성은 외부 클라우드 LLM API를 사용하지 않습니다.

## 처음 실행하기

### 1. 저장소 받기

```bash
git clone https://github.com/woojin0220/2026-TechForImpact-DARI.git
cd 2026-TechForImpact-DARI
```

### 2. Android SDK 경로 설정

Android Studio에서 프로젝트를 열면 SDK 경로를 자동으로 설정할 수 있습니다. 명령줄에서 빌드한다면 프로젝트 루트에 커밋되지 않는 `local.properties`를 만들고 자신의 SDK 경로를 지정합니다.

```properties
sdk.dir=/사용자별/Android/Sdk/경로
```

다른 사람의 `local.properties`를 복사하면 안 됩니다. 이 파일은 각 개발 환경마다 달라 Git에서 제외되어 있습니다.

### 3. Ollama와 모델 준비

Ollama를 실행한 뒤 두 테스트 모델을 내려받습니다.

```bash
ollama serve
```

다른 터미널에서 실행합니다.

```bash
ollama pull qwen3:4b
ollama pull llama3.2:3b
```

macOS에서 Homebrew 서비스로 Ollama를 실행하는 경우에는 `ollama serve` 대신 다음 명령을 사용할 수 있습니다.

```bash
brew services start ollama
```

모델 설치 여부는 다음 명령으로 확인합니다.

```bash
ollama list
```

### 4. DARI 로컬 검증 서버 실행

프로젝트 루트에서 실행합니다.

```bash
python3 local_verification_server.py
```

정상적으로 실행되면 다음 주소가 표시됩니다.

```text
DARI local verification server: http://127.0.0.1:8765
```

이 터미널은 앱을 테스트하는 동안 계속 실행해 두어야 합니다.

### 5. Android 앱 빌드

macOS 또는 Linux:

```bash
./gradlew assembleDebug
```

Windows:

```powershell
gradlew.bat assembleDebug
```

생성된 APK는 다음 위치에 있습니다.

```text
app/build/outputs/apk/debug/app-debug.apk
```

Android Studio를 사용하는 경우 API 23 이상의 에뮬레이터를 선택해 Run을 실행하면 됩니다.

## `10.0.2.2:8765`의 의미

현재 앱은 Android Emulator에서 실행하는 개발 환경을 기준으로 구성되어 있습니다. Android Emulator 안에서 `10.0.2.2`는 특정 팀원의 컴퓨터 주소가 아니라 **에뮬레이터를 실행한 개발 컴퓨터의 루프백 주소**를 가리키는 예약 주소입니다.

따라서 각 개발자는 자신의 컴퓨터에서 다음 두 프로그램을 실행합니다.

1. Ollama 서버: `127.0.0.1:11434`
2. DARI 검증 서버: `127.0.0.1:8765`

에뮬레이터의 앱은 `http://10.0.2.2:8765`로 요청해 같은 개발 컴퓨터의 DARI 서버에 연결합니다. 기본 주소는 [`app/build.gradle.kts`](app/build.gradle.kts)의 `VERIFICATION_API_BASE_URL`에 정의되어 있습니다.

이 주소는 실제 Android 휴대전화에서는 동작하지 않습니다. 실제 기기 테스트는 서버 주소, 네트워크 바인딩, HTTPS와 접근 통제를 별도로 설계해야 합니다. 민감한 진술을 다루므로 단순히 서버를 `0.0.0.0`으로 공개하는 방식은 사용하지 마세요.

## 번역과 검증 데이터 흐름

### 기기 안에서 처리하는 정보

- 신청자가 입력한 모국어 답변
- 선택 언어에서 영어로 번역한 결과
- 영어에서 한국어로 번역한 결과
- 문항별 최종 번역본

ML Kit 언어 모델은 최초 실행 시 인터넷으로 내려받지만, 모델 다운로드 후 진술 번역 자체는 기기에서 처리됩니다.

### 로컬 검증 서버로 보내는 정보

- 사용자가 확인한 개인정보 제외 원문
- 사용자가 확인한 개인정보 제외 영어 번역본
- 선택한 언어와 검증 모델 이름

한국어 참고본은 LLM 검증 요청에 포함하지 않습니다. 현재 서버는 요청 내용을 별도 파일이나 데이터베이스에 저장하지 않습니다.

## 개인정보 마스킹 상태

현재 앱은 정규식으로 이메일, 전화번호 형태, 일부 긴 식별번호 형태를 찾아 치환한 뒤 사용자가 실제 전송본을 수정하게 합니다. 이름, 주소, 여권번호, 국가별 식별번호를 완전하게 탐지하지 못하며 날짜를 전화번호로 오인할 가능성도 있습니다.

따라서 현재 기능을 개인정보가 완전히 제거된 것으로 간주하면 안 됩니다. 사건 날짜와 생년월일의 구분, 다국어 이름·주소 탐지, 국가별 식별번호 규칙은 향후 논의 사항입니다.

## 검증 결과의 의미

LLM은 다음과 같은 번역 변화의 후보를 찾습니다.

- 원문 내용 누락 또는 근거 없는 추가
- 부정·긍정 반전
- 확실성이나 강도의 변화
- 행위자·피해자·책임 주체 변경
- 날짜·기간·빈도·사건 순서 변경
- 인과관계나 동기 변경
- 피해·위협·강요 정도의 강화 또는 약화
- 원문에 없는 법률적·설득적 표현

결과의 `유리하게 강화`, `불리하게 약화`, `방향 불명확`은 번역 변화의 방향을 설명할 뿐 심사 결과를 예측하지 않습니다. 작은 로컬 모델은 오류를 놓치거나 유형을 잘못 분류할 수 있으므로 원문 작성자, 통역가 또는 법률 전문가가 최종 확인해야 합니다.

## 문제 해결

### 앱에서 로컬 검증 서버에 연결하지 못하는 경우

- `local_verification_server.py` 터미널이 실행 중인지 확인합니다.
- `ollama list`에 두 모델이 표시되는지 확인합니다.
- Ollama가 `127.0.0.1:11434`에서 실행 중인지 확인합니다.
- Android Emulator를 사용하고 있는지 확인합니다. 실제 기기에서는 `10.0.2.2`가 동작하지 않습니다.
- 8765번 포트를 다른 프로그램이 사용하고 있지 않은지 확인합니다.

### 최초 번역 모델 다운로드가 실패하는 경우

- 에뮬레이터의 인터넷 연결을 확인합니다.
- Wi-Fi 네트워크로 인식되는지 확인합니다.
- 선택 언어→영어와 영어→한국어 모델이 모두 필요합니다.

### 첫 검증이 느린 경우

Ollama가 모델을 메모리에 처음 올리는 과정에서 시간이 걸릴 수 있습니다. 16GB 메모리 환경에서는 다른 대용량 프로그램을 함께 실행하면 응답이 더 느려질 수 있습니다.

## 메타데이터 중심 대화 테스트 모드

첫 화면의 **Conversation test · English → Korean**으로 시작합니다. 고정된 문항별 질문 대신 영어로 자유롭게 이야기하면 핵심 메타데이터를 추출하고, 빈 항목이나 상충하는 항목에 대해 LLM이 최대 두 번 추가 질문합니다. 모른다고 답한 항목을 억지로 채우지 않습니다. **Generate an example**은 현재 질문과 이전 답변을 참고해 영어 가상 답변을 생성합니다. 입력란만 채우며 전송은 사용자가 직접 합니다. 입력 중인 내용이 있으면 덮어쓰지 않고, 테스트 모드에서만 사용할 수 있습니다. 예시 사용 여부는 전체 JSON에 기록합니다. 언제든 **Finish**로 수집을 마칠 수 있습니다.

초안은 전체 수집 메타데이터를 문맥으로 참고하되 각 문항에 연결된 근거를 사용해 작성합니다. 섹션과 문항 카드를 구분하며 한국어 초안이 표시되면 각 항목의 영어 역번역을 자동으로 준비합니다. 수정 대화에서도 현재 문장과 제안 문장의 역번역을 자동으로 준비합니다. 같은 모델의 수정·역번역 요청은 순차 실행하고 실패한 경우에만 재시도 버튼을 표시합니다. 한국어 문장이 바뀌면 이전 역번역은 숨겨지고 자동으로 다시 번역합니다. 역번역은 세션 내 임시 표시이며 내보내기·자동 저장에 포함되지 않습니다. 동일 모델의 역번역은 의미 보존을 보장하지 않으며 독립적 원문-초안 검증기는 아직 연결하지 않았습니다.

개인정보 양식과 후속 전체 질문은 생략합니다. 생략된 사실을 자동으로 채우지 않으며 화면·TXT·JSON에 테스트용임을 표시합니다. 실제 제출용 신청서가 아닙니다. 전체 작성 모드는 유지되고, 입력한 작업이 있을 때 새 테스트로 덮어쓰는 버튼은 표시하지 않습니다.

## 초안의 문장별 대화 수정

14번 초안의 텍스트 답변에서 **문장별 대화로 다듬기**를 선택합니다. 수정할 문장을 고른 뒤 요청하면 모델이 설명 또는 수정안을 반환합니다. **이 수정안 반영**을 눌러야 해당 문장이 바뀌며, 문장별 대화 유지·제안 거절·마지막 수정 되돌리기를 지원합니다.

- 제공받은 `DARI_TXT_Mac`의 문장 분리, 대화, 승인 및 되돌리기 상태 로직을 `capacitor-web/src/revision`으로 통합했습니다. 독립 실행기와 설치 스크립트는 사용하지 않습니다.
- 기존 `generateIntakeModel` 경로를 공유합니다. 브라우저에서는 설정된 작성 서버, 모바일에서는 네이티브 모델을 사용하며 외부 서비스로 자동 전환하지 않습니다. 이번 확인은 Mac 로컬 모델 기준이며 모바일 실기기 검증은 별도입니다.
- 선택 문장, 앞뒤 문장과 해당 문장의 최근 대화만 모델에 전달합니다. 사실·부정·불확실성을 보존하고 사실 정정은 수집 단계로 안내하도록 요청합니다. 이는 프롬프트 지침이며 모델의 의미 보존을 보장하는 검증기는 아닙니다.
- 승인된 문장은 `question14`와 최종 TXT에 반영됩니다. 전체 JSON의 `draftReviews`에는 문장별 대화와 수정 이력이 포함됩니다. 사용자 원문·메타데이터·최초 생성 문장과 근거는 덮어쓰지 않습니다. 수정 문장의 근거는 자동으로 재연결되거나 검증되지 않습니다.
- 새 원문 입력이나 초안 재생성 시 기존 수정 작업을 무효화합니다. 직접 텍스트를 편집하면 해당 항목의 문장 수정 기록을 초기화하므로 필요한 이력은 먼저 내보내세요.
- 자동 저장·JSON 작업 복원·별도 TXT 업로드·암호화 작업 파일 저장은 이번 통합에 포함하지 않았습니다. 영어 테스트에서는 선택 문장과 수정 제안의 영어 역번역을 자동 표시합니다. 내보낸 JSON과 TXT는 평문이므로 개인정보를 포함한 실제 자료의 보관·공유에 주의해야 합니다.

## 현재 MVP에서 구현하지 않은 항목

- 모국어로 검수된 문항 번역. 웹 앱의 문항 문면은 공식 서식 한국어·영어입니다
- 공무원 기재란, 자필 서명, 공식 서식 파일 출력
- Word 또는 공식 신청서 형식 출력
- 운영용 인증·HTTPS·접근 권한 관리
- 국가별 개인정보 탐지
- 검증 모델 평가셋과 품질 기준
- 통역가·법률가 검토 및 수정 이력

구현을 변경하기 전에 [향후 논의·결정 사항](docs/OPEN_DECISIONS.md)에서 아직 확정되지 않은 내용을 확인해 주세요.
