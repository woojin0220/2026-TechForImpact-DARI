# DARI MVP 구현 문서

## 1. 목적과 범위

DARI MVP는 난민인정신청자가 공식 문항을 모국어로 이해하고 답변하면 영어 신청서 초안과 한국어 참고본을 만드는 Android 프로토타입입니다. 모든 문항 작성이 끝난 뒤 원문과 영어 번역문을 비교해 번역 과정에서 발생한 의미 왜곡 후보를 안내합니다.

현재 구현은 작성·번역·검증 흐름을 확인하기 위한 프로토타입입니다. 법률 자문, 진술의 신빙성 판단, 난민 인정 가능성 예측, 심사에 유리한 문장 생성은 범위에 포함하지 않습니다.

## 2. 시스템 구성

```text
Android 앱·에뮬레이터
  ├─ 문항 표시와 모국어 답변 입력
  ├─ ML Kit 온디바이스 번역: 선택 언어 → 영어 → 한국어
  ├─ 영어·한국어 최종본 표시
  └─ 개인정보 제외본 전송
          │ 10.0.2.2:8765
          ▼
Mac 로컬 검증 서버
  └─ Ollama: Qwen3 4B 또는 Llama 3.2 3B
          └─ 유형별 번역 왜곡 후보를 JSON으로 반환
```

에뮬레이터에서 `10.0.2.2`는 호스트 Mac을 가리킵니다. 검증 서버는 Mac의 `127.0.0.1:8765`에만 바인딩하므로 현재 구성에서는 LAN이나 공개 인터넷에 노출되지 않습니다.

## 3. 사용자 흐름

1. 작성 언어와 검증 모델을 선택합니다.
2. 선택 언어→영어 모델과 영어→한국어 모델을 Wi-Fi에서 내려받습니다.
3. 신청자가 각 문항의 번역을 읽고 모국어로 답변합니다.
4. 답변은 기기 안에서 영어로 번역된 뒤 다시 한국어로 번역됩니다.
5. 모든 문항 작성 후 원문·영어·한국어를 문항별로 확인합니다.
6. 검증을 선택하면 전체 원문과 전체 영어본에서 자동 탐지 가능한 개인정보를 가립니다.
7. 사용자가 서버 전송본을 직접 확인하고 남은 개인정보를 수정합니다.
8. Mac 로컬 LLM이 전체 원문과 영어본을 비교합니다.
9. 앱은 왜곡 여부와 유형, 방향, 심각도, 해당 문항, 원문·번역 발췌, 설명을 표시합니다.

## 4. 현재 지원하는 언어

UI에는 러시아어, 아랍어, 프랑스어, 페르시아어 선택지가 있습니다. 이 네 언어는 기술 흐름을 시험하기 위한 데모 범위이며 공식 지원 언어로 확정된 것은 아닙니다. 문항 번역 역시 실제 제공 전에 공인 통역 또는 관련 전문가의 검토가 필요합니다.

## 5. 번역 구현

Android 앱은 Google ML Kit 온디바이스 번역을 사용합니다.

- 1차 번역: 선택 언어 → 영어
- 2차 번역: 영어 → 한국어
- 최초 모델 다운로드 이후 진술 번역은 기기 내부에서 처리
- 영어본은 신청서 초안의 기준 번역본
- 한국어본은 지원자·활동가의 확인을 돕는 참고본

현재 한국어는 원문에서 직접 번역하지 않고 영어 번역본을 다시 번역합니다. 따라서 영어 번역의 오류가 한국어에 이어질 수 있으며, 한국어본을 독립적인 정답이나 검증 기준으로 사용할 수 없습니다.

## 6. 개인정보 처리

앱은 현재 정규식으로 이메일, 전화번호 형태, 13자리 식별번호 형태를 치환합니다. 이후 사용자가 전송본을 직접 수정할 수 있습니다.

현재 방식은 이름, 주소, 여권번호, 국가별 식별번호를 안정적으로 탐지하지 못합니다. 전화번호 규칙이 날짜를 오인할 가능성도 있습니다. 따라서 자동 마스킹 완료를 보장하지 않으며, 세부 기준은 추후 결정 사항으로 남겨 두었습니다.

검증 서버에는 사용자가 확인한 전체 원문과 전체 영어본만 전송합니다. 한국어 참고본은 검증 요청에 포함하지 않습니다.

## 7. 번역 왜곡 검증

로컬 서버는 다음 항목을 LLM 프롬프트로 확인합니다.

- 원문 내용의 누락
- 원문에 없는 내용의 추가
- 부정 또는 긍정의 반전
- 확실성·추정·강도의 변화
- 행위자·피해자·책임 주체의 변화
- 날짜·기간·빈도·순서의 변화
- 장소·신원·숫자·관계의 변화
- 인과관계나 동기의 변화
- 피해·위협·강요 정도의 강화 또는 약화
- 원문에 없는 법률적·설득적 표현
- 문항 간 모순

왜곡 방향은 `유리하게 강화`, `불리하게 약화`, `방향 불명확`으로 표시합니다. 이는 번역문이 원문보다 강해졌는지 약해졌는지를 설명하는 분류이며 실제 심사 결과를 예측하지 않습니다.

현재 검증은 단일 LLM 호출에 의존합니다. 모델이 유형이나 방향을 잘못 분류하거나 일부 오류를 놓칠 수 있으므로 결과에는 발췌문과 설명을 함께 표시하고 전문가 확인을 요구합니다.

## 8. 주요 코드

- `DariApp.kt`: 화면과 전체 사용자 흐름
- `TranslationRepository.kt`: 온디바이스 영어·한국어 번역
- `VerificationRepository.kt`: 개인정보 치환과 검증 API 호출
- `local_verification_server.py`: Ollama 연결과 검증 프롬프트
- `app/build.gradle.kts`: Android 의존성과 로컬 서버 주소

## 9. 실행과 데이터 보관

앱의 답변과 번역은 현재 메모리에만 저장되며 앱을 다시 시작하면 사라집니다. 서버도 요청 내용을 별도 저장하지 않습니다. 운영 단계에서는 임시 저장, 암호화, 삭제 시점, 접근 통제, 로그 정책을 별도로 설계해야 합니다.

## 10. 현재 한계

- 공식 신청서 전체 문항이 아니라 14번 일부 문항만 구현했습니다.
- 지원 언어와 문항 번역이 확정되지 않았습니다.
- 한국어 연쇄 번역의 품질을 평가하지 않았습니다.
- 개인정보 탐지 범위와 오탐 처리 기준이 정해지지 않았습니다.
- 검증 모델의 정확도·재현율·일관성을 측정할 평가셋이 없습니다.
- Word 또는 공식 신청서 형식 출력이 구현되지 않았습니다.
- 법률가·통역가 검토 및 수정 이력 기능이 없습니다.
