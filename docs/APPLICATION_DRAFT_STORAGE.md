# 신청서 저장과 서비스 계정 연결

로그인 상태는 `platform/AuthContext.tsx`에서 서비스 전체에 제공됩니다.
신청서와 커뮤니티는 같은 인증 세션을 사용하며, 신청서 소유자는 커뮤니티
닉네임이나 회원 유형이 아닌 `session.user.id`로 구분합니다.

현재 신청서 저장은 `sessionStorage`입니다. 새로고침과 화면 이동은 복원하지만
탭이나 앱 종료 이후의 보존, 다른 기기 복원, 서버 동기화는 제공하지 않습니다.
로그인 사용자별 키와 게스트 키를 분리하고, 계정 변경 시 신청서 화면을 새로
마운트합니다. 게스트 작성분은 기존 키에서 읽으며 로그인 계정으로 자동 복사하지
않습니다. 로그아웃해도 다른 계정의 작성분을 불러오지 않습니다.

## DB 어댑터를 연결할 위치

`src/application/repository.ts`의 `ApplicationDraftRepository`는 비동기
`load()`와 `save(draft)` 계약입니다. 화면은 저장 매체를 직접 호출하지 않고
`useDraft.ts`를 통해 이 계약을 사용합니다. 현재 `AppTabs.tsx`에서 사용자 ID에
연결한 `sessionDraftRepository`를 주입합니다. DB 연동 시 이 어댑터만 교체합니다.

- `scope`는 계정 변경 때 달라져야 합니다. 계정 전환 시 이전 비동기 로드 결과는
  무시하고, 저장 요청은 생성 당시 소유자에게만 남깁니다.
- 저장은 순서대로 실행해 이전 응답이 최신 입력을 덮어쓰지 않게 합니다.
- 초기 로드가 실패하면 빈 초안을 자동 저장하지 않습니다. 오류를 표시하고 기존
  저장 내용을 보존합니다.
- 현재 화면 상태와 원문, 답변별 언어, 한국어 번역, 번역 당시 원문을 저장합니다.
  번역 당시 원문이 달라지면 다운로드 전에 다시 번역합니다.

향후 DB 레코드는 `user_id`, `version`, `language`, `answers`, `updated_at`,
동시 수정 검사용 `revision`을 갖도록 설계할 수 있습니다. 여러 기기 동시 수정은
현재 구현 범위에 없으므로 DB 연결 시 revision을 비교해 충돌을 처리해야 합니다.
`ApplicationDraft.version`은 데이터 형식 버전이며 동시 수정 revision이 아닙니다.

서버/RLS는 인증된 사용자와 소유자가 같은지 읽기와 쓰기 양쪽에서 검사해야 합니다.
클라이언트가 넘기는 user ID만으로 권한을 판단하지 않습니다. 신청서는 커뮤니티
게시물과 별도로 저장하며 커뮤니티 공개 정책이나 운영자 조회 권한을 상속하지
않습니다. 이 PR에는 DB 테이블, 마이그레이션, 네트워크 저장 호출이 없습니다.
