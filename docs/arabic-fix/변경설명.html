1. 원인은 어디에 있었나?

A. 한국어/영어만 있는 조건 분기

원본 JourneyPanels.tsx 40–64행은 language === 'ko'만 검사했습니다. 아랍어 ar는 이 조건이 거짓이므로 영어 안내·버튼·확인 문구를 받았습니다. StatementDetails.tsx 8행의 번역 함수도 같은 구조였습니다.

원본의 핵심 분기
const ko = language === 'ko';
<button>{ko ? '수정' : 'Correct'}</button>
수정 후: 언어별 키 조회
const copy = journeyCopyFor(language);
<button>{copy.correct}</button>
// ar.correct = 'تصحيح'

선택 언어를 기준으로 문구 사전을 선택하도록 바꿨고, 영어에 있는 키가 아랍어에도 모두 있도록 타입과 검사로 확인합니다.

B. 사전에 없으면 영어를 보여 주는 fallback

원본 FormStage.tsx 10–13행과 App.tsx의 requirementLabel()은 사전에서 해당 한국어 라벨을 찾지 못하면 영어를 반환했습니다. 공식 양식 사전은 대체로 준비돼 있었지만, 이후 추가된 대화 메타데이터·보조자·그룹 문구 92개의 아랍어 매핑이 빠져 있었습니다.

원본
return hasQuestionPhrase(ko)
  ? localize(language, ko)
  : en;
수정 후
return localizedLabel(language, ko, en);
// 현재 스키마·카탈로그의 모든 알려진 라벨은 정확한 ar 매핑
// 새 누락 키는 영어 대신 아랍어로 '번역 미지원' 안내

알려진 문항은 정확한 아랍어 문구로 연결합니다. 향후 누락 키가 추가되면 감사 테스트가 실패하고 화면에서는 다른 질문이나 영어로 조용히 바꾸지 않습니다.

C. 전역 RTL 설정만으로 하위 화면이 번역되지는 않음

원본에도 document.documentElement.lang = language와 dir = direction이 있었습니다. 그러나 App.tsx 430–442행은 최종 초안의 안내·문항을 영어 또는 한국어로만 골랐고, SentenceReview.tsx 45행은 편집 화면을 dir="ltr"로 고정했습니다. 운영자 설정도 한국어·LTR 고정이었습니다.

원본
<section lang={language === 'en' ? 'en' : 'ko'} dir="ltr">
  ...
</section>
수정 후
<section lang={language} dir={direction}>
  <FieldInput language={language}
    valueLanguage="ko" ... />
</section>

안내와 버튼은 아랍어 RTL, 실제 한국어 초안 값은 lang="ko" dir="ltr"로 분리했습니다.

D. 로딩·오류·수정 대화는 별도 경로였음

원본 EnglishMeaning.tsx 23·32–33행에는 영어 오류·Loading…·재시도 버튼이 직접 들어 있었습니다. 오류 뒤에 엔진의 원시 오류 문자열도 붙였습니다. revision/model.mjs 11–15행은 영어 이외 수정 대화를 한국어로 요청했습니다.

수정본은 로딩·취소·재시도·오류 종류를 번역 키로 표시하고, 원시 영어·한국어 엔진 오류를 신청자 안내에 직접 덧붙이지 않습니다. 문장 수정 대화는 아랍어 설명을 요청하며 다른 언어 응답은 재시도·오류 처리합니다. 대체 문장 자체는 한국어를 유지합니다.

E. 영어 전용 개발 테스트가 일반 시작 화면에 노출됨

짧은 대화 테스트는 원래 영어로 전환하도록 작성된 개발 흐름이었습니다. 이 동작을 일반 아랍어 흐름과 섞지 않도록 생산용 시작 화면에서 감추고, 개발 화면에서는 영어 테스트라는 사실을 선택 언어로 명시합니다. 실제 아랍어 대화의 시작 질문과 후속 질문은 아랍어 세션 언어를 유지합니다.

  2. 기본정보에서 다음 화살표가 왼쪽이고, 날짜·숫자·모델 태그가 뒤집히지 않는지 봅니다.
  3. 더 보기, 수집 내용, 정정, 미확인 항목, 원문 보기, 저장 안내와 접근성 이름을 확인합니다.
  4. 모델 없음·연결 실패·잘못된 응답·중지 후 오류가 원시 영어/한국어가 아닌 아랍어로 설명되는지 확인합니다.
  5. 수정창·최종 초안에서 주변 안내는 RTL, 한국어 텍스트는 LTR이며 긴 문장이 잘리는지 확인합니다.
  6. 아랍어 의미 확인·수정안 반영을 번역된 UI만으로 승인할 수 없고 제한이 아랍어로 설명되는지 확인합니다.
  7. 문구 키를 일부러 빼거나 치환 자리를 바꾸면 audit:ar와 해당 테스트가 실패하는지 확인합니다.

7. 그대로 남는 한계

  • 아랍어 역번역·최종 의미 확인 기능은 추가하지 않았습니다. 지원되지 않는 검토 완료·수정안 반영은 비활성화하고, 이유를 아랍어로 안내합니다. 미확인 작업 기록 저장은 기존대로 가능합니다.
  • 프랑스어·러시아어·페르시아어의 기존 번역 범위는 유지했습니다. 이번 결과를 6개 언어 모두의 현지화 완료로 해석하면 안 됩니다. 브라우저 기본 모델은 저장소 원본과 동일한 gemma4:e4b로 유지합니다.
  • 아랍어 문자가 있는지 검사하는 방어 로직은 다른 언어만으로 된 응답을 막는 보조 검사입니다. 아랍어 문법·내용·혼합 언어·의미 보존을 완전히 검증하지는 않습니다.
  • 아랍어 원어민의 번역 감수, 모든 실제 모바일 기기·키보드·스크린리더 환경 시험은 수행하지 않았습니다.
  • 새로고침 후 작업 복원과 실제 번역의 의미 정확성은 별도 기능·품질 과제로 남습니다.
