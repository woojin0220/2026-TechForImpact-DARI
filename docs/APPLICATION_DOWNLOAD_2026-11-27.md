# 신청서 다운로드 화면과 PDF·HWP 출력

2026-11-27 · `feat/application-ui`

## 사용자 흐름

작성본 다운로드 → 다운로드 전용 화면 → 미완료 문항의 **번역하기 / 번역 확인하기** → 사용자 확인 → 다운로드 화면 복귀 → PDF 또는 HWP 다운로드.

선택한 파일 형식은 문항을 확인하고 돌아와도 유지. 이미 번역된 답변은 재번역하지 않음. 단답형은 확인 체크 후 바로 복귀하고, 서술형은 확인 후 저장하면 복귀. 문항 번호·원래 질문·필요한 행동을 함께 표시.

**인쇄 후 자필 작성·서명 필요**를 다운로드 화면의 강조 상자로 안내. 원본 서약·서명란은 자동 입력하지 않음. 작성하지 않은 문항은 빈칸으로 유지.

## 출력 구현

| 구분 | 동작 |
| --- | --- |
| 공통 | `answerLayout.ts`: 현재 번역·명시적 사용자 확인이 모두 유효한 답변만 출력. 모델 호출 없음. 원문에서 추론하거나 미작성 값을 임의로 채우지 않음 |
| PDF | 2024-12-03 공식 22쪽 PDF에 답변 삽입. 긴 답변은 번호 별지와 연결. NanumGothic 전체 임베딩: subset 적용 시 실제 PDF 렌더러에서 한글이 누락되는 문제를 확인했으므로 subset 비활성화 |
| HWP | 2024-12-03 공식 HWP 5 원본의 실제 표·문단 편집. 확장자만 바꾼 HTML·DOCX가 아님. 문항 라벨·페이지·빈 문단을 대조해 입력. 긴 답변·복합 답변은 번호 별지. 원본 스크립트·오래된 미리보기 제거 |
| Word | 기존 Word encoder는 공통 레이아웃을 사용하도록 정리. 이번 다운로드 화면은 PDF·HWP 제공 |

2024년 HWP 출처: 국가법령정보센터 `flSeq=146016517`. SHA-256과 URL은 `public/forms/refugee-application-2024-hwp.source.json`에 기록. 연결된 PDF `flSeq=146016519`와 기존 앱 PDF `flSeq=146016207`의 22쪽 텍스트가 일치함을 대조.

## 확인 결과

- 전체 테스트 329개·TypeScript·프로덕션 빌드 통과.
- 6개 UI 언어, 320/390px에서 문항 해결·다운로드 복귀·파일 형식 유지·실제 PDF/HWP 다운로드 확인.
- 다운로드 시 모델 호출 없음. 번역이 필요한 경우에만 번역 버튼의 요청 1회 발생. UI 검증에는 모의 번역 응답 사용.
- PDF 26쪽 긴 답변 예시를 PDFium으로 렌더링하고 전체 진술 보존 확인.
- HWP를 설치된 Windows 한글에서 직접 열고 PDF로 인쇄. 긴 답변 예시 27쪽과 전체 문항 예시 49쪽 확인. 원본 22쪽 순서와 서약·서명란 유지.
- 서명·서약이 있는 21/22쪽 및 안내 1/2쪽의 원본 문단이 변하지 않는지 자동 검사.
- 기존 2019년 `src/export/*` 경로는 별도 legacy 출력으로 유지. 현재 신청서 화면은 `src/application/pdf.ts`, `src/application/hwp.ts` 사용.

Android 실기기의 파일 저장 동작, 운영 모델 품질과 법적 접수 적합성은 위 파일 생성·렌더링 검증과 별개. 이번 변경은 로컬 작업본이며 push·PR·병합 미수행.
