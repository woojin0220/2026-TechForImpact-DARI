# 커뮤니티 사용자 피드백용 통합본

## 이번 구성

기존 벤치마킹(`COMMUNITY_UX_PLAN.md`)의 제목 중심 탐색, 정보의 재발견, 가벼운 참여를 적용했다. 새 커뮤니티 플랫폼으로 교체하지 않고 기존 Q&A·생활정보·기관 공지와 3개 앱 탭을 유지했다.

- 앞선 `feat/community-ux`의 커밋 1eaf240을 현재 신청서·P0 기반으로 통합. 통합 커밋은 aa30e10. 검색·답변 없는 질문·목록 정리·검색 조건 보존을 중복 구현하지 않았다.
- 글 상세의 저장 버튼과 홈의 ‘저장한 글’. 게시판을 가로질러 저장 글을 다시 조회·검색할 수 있다. 삭제·차단·숨김 등으로 볼 수 없는 글은 조회 결과에 표시하지 않는다.
- 게시글 작성 중 자동 임시 저장과 홈의 이어 쓰기. 뒤로 가기·하단 탭 이동·새로고침 후 복구, 명시적 임시 글 삭제, 게시 성공 후 해당 임시 글 정리.
- 작성 언어 선택. 글의 언어를 앱 화면 언어와 독립적으로 저장하고 번역 adapter에 전달. 글 상세에 원문 언어 표시.
- 중복 제출 잠금, 게시 실패 시 입력 유지, 오래된 게시 응답이 새 임시 글을 삭제하지 않도록 보호.
- Supervisor 전용 가상 글 보충. 일반 사용자·운영 DB에 샘플 글을 추가하는 작업은 하지 않음.
- 좁은 화면의 헤더·접근성 이름, 개발용 안내 막대 아래의 고정 헤더 위치 조정.

## 저장 범위

| 대상 | 위치·수명 | 계정 경계 |
| --- | --- | --- |
| 작성 중 게시글 | `sessionStorage`; 현재 브라우저 탭. 게시/삭제 전까지 복구. 탭 종료·앱 데이터 삭제 뒤 보존 보장 아님 | 계정 ID별 키. 다른 계정으로 자동 이전 안 함 |
| 저장한 글 | `localStorage`; 글 ID 최대 200개. 본문을 저장 목록에 복제하지 않음 | 계정 ID별 키. 다른 기기·브라우저와 서버 동기화하지 않음 |
| 게시한 글·댓글 | 기존 Supabase, 기존 접근·운영 정책 유지 | 서버 RLS. 개발용 Supervisor는 별도 로컬 가상 adapter |

자동 임시 저장은 신청서나 개인 일정을 복사하는 기능이 아니다. 공개하기 전에는 사용자가 게시 버튼을 눌러야 한다. 댓글 임시 저장·게시글 수정 UI·서버의 전송 재시도 idempotency·댓글 알림·신고 관리 화면은 이번 기능에 포함하지 않았다.

## 사용자 피드백 과제

1. 필요한 질문을 검색하고 답변 없는 질문을 찾는다.
2. 글을 열고 저장한 뒤 ‘저장한 글’에서 다시 찾고 저장을 해제한다.
3. 글 제목과 내용을 작성하고 다른 앱 탭을 다녀온다. 이어 쓰기와 새로고침 복구를 확인한다.
4. 작성 언어를 선택하고 게시한다. 글이 어디에 공개되고 어떤 언어로 기록되는지 이해되는지 확인한다.
5. 생활정보·공지·댓글·신고·차단의 위치가 예상과 맞는지 확인한다.

상단의 기능 수가 부담스러운지, 저장/임시 저장의 차이를 이해하는지, 제목과 본문 미리보기의 밀도가 적절한지, 글쓰기 중 언어 선택이 방해되는지 의견을 받는다. 사용자 테스트로 효과를 확인했다고 미리 주장하지 않는다.

## 검증 범위

315개 테스트와 웹 빌드, 6개 언어·320/390px의 웹 UI 확인. 글 저장 후 새로고침, 임시 글 취소/탭 이동/새로고침, 언어 유지, 게시 성공 후 정리, 검색, 게시 실패 시 입력 보존·연속 제출 잠금 확인. 데이터는 Supervisor 가상 데이터 사용.

운영 Supabase에서 새 조회를 실제 실행하거나 Android의 실제 번역 엔진·APK를 검증한 결과는 아니다. Supervisor에서는 번역 엔진을 연결하지 않는다. 외국어 가상 글은 원문으로 보이며 기존 실제 기기 번역 경로와 구분해야 한다.
