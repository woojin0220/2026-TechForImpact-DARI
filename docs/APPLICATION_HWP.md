# 신청서 원본 HWP 출력 (#9)

## 사용자 흐름

한국어 초안 → 신청서 내보내기 → 전체 답변 검토 → HWP 만들기 → HWP 다운로드.
또는 초안 화면의 ‘한국어 초안 저장 (HWP)’을 눌러 바로 생성·다운로드한다. 기존 TXT 버튼을 대체하며 클릭할 때마다 현재 답변으로 새로 생성한다. 생성 중 중복 클릭을 막고 답변 변경이나 화면 이동 중에는 이전 요청의 다운로드를 취소한다. 생성 실패 시 오류를 표시한다.
다운로드한 파일은 한글 앱에서 편집한다. 브라우저 미리보기는 별도로 생성한 PDF를 사용한다.
HWP와 PDF는 동일한 현재 답변을 사용하지만 페이지 수와 별지 배치는 같지 않을 수 있다.

PDF나 HTML의 확장자를 HWP로 바꾸지 않는다. 원본 HWP 5의 OLE 스트림과 본문 레코드를 수정해 실제 `.hwp`를 생성한다. 서버 전송이나 한컴 클라우드 변환은 없다.

## 파일 구조와 범위

- 원본은 사용자가 제공한 2019.12.31 개정본이다. 최신 시행 서식으로 인증한 것이 아니며 실제 제출 전에 최신 서식을 확인해야 한다.
- `src/export/hwpBinary.ts`: HWP 레코드 헤더, UTF-16LE 본문, 문단과 표 셀의 계층을 처리한다.
- `src/export/hwp.ts`: 선택된 체크박스를 ✓로 표시한다. 비어 있는 원본 문단에 답변을 넣고, 필요한 경우 해당 셀의 문단 목록 수와 마지막 문단 표시를 갱신한다. 표의 데이터 셀은 세로 중앙 정렬하며 남는 빈 문단을 제거한다. 질문과 답변이 함께 있는 셀의 공식 질문 배치는 변경하지 않는다.
- `src/export/hwpTables.ts`: 원본 표의 페이지/행 매핑. HWP의 자동 높이 셀은 저장된 높이가 0인 경우가 있어 PDF 좌표만으로 표를 매핑하지 않는다. 표 열 수와 원래 빈칸 여부를 검증한다.
- 짧은 표는 원본에 채우고, 칸을 넘는 표와 긴 진술은 번호 별지로 보낸다. 추정 폭을 보수적으로 사용해 잘림을 피한다. 별지에서는 40줄마다 페이지를 나누고 계속 페이지에 문항 번호를 반복한다.
- 빈칸을 ‘해당 없음’으로 바꾸지 않는다. 모름/해당 없음은 예/아니요와 구분하며 선택지 체크박스를 임의 선택하지 않는다. 미해결·미작성 항목은 별도 출력 검토 목록에 남는다.
- 문장 에디터에서 승인한 현재 `session.question14` 및 `session.form`만 사용한다. 모델을 다시 호출하거나 메타데이터로 이전 초안을 재작성하지 않는다.
- 서약, 서명, 동의 표시, 신청일과 공무원 작성란은 채우지 않는다. 15번처럼 아직 수집하지 않은 항목은 비워두고 확인할 수 있게 한다. 자동 제출하지 않는다.
- 원본의 스크립트 스트림과 낡은 미리보기 이미지는 결과에서 제외한다. 새 미리보기 텍스트에는 현재 답변의 일부가 담기므로 다운로드 파일 자체에 개인정보가 포함된다는 점은 PDF와 같다.

구조 처리는 [한컴 공개 HWP 5.0 rev 1.3 명세](https://cdn.hancom.com/link/docs/한글문서파일형식_5.0_revision1.3.pdf)를 기준으로 독립 구현했다. OLE 처리는 `cfb`, 압축은 `fflate`를 사용한다. 원본 이외의 HWP를 업로드받아 임의로 채우는 범용 편집기가 아니다.

## 호환성 수정과 검증

- 압축된 본문을 다시 읽어 모든 선택지의 실제 HWP 라벨을 대조한다.
- 새 빈 문단은 PARA_TEXT에 CR만 쓰지 않는다. 문단 헤더의 암묵적 줄바꿈을 사용해야 Mac 한컴오피스의 네이티브 로더에서 정상적으로 열린다. 이 회귀 조건을 테스트한다.
- HWP 문단의 레이아웃 캐시도 작성한다. 원본 답변 칸의 캐시는 유지하고 별지의 새 문단에는 글자 수, 글자 모양, 줄 배치 정보를 함께 제공한다.
- 생성 파일을 OLE/HWP 파서로 다시 열어 긴 진술 끝, 불확실성/부정 표현, 최신 수정문, 모든 표/문항의 값과 미작성 상태가 보존되는지 확인한다.
- 서약 및 신청란이 있는 원본 2·21·22쪽의 문단 내용이 바뀌지 않는지 검사한다.
- Mac 한컴오피스 한글에서 가상 HWP를 직접 열어 이름, 날짜, 직업, 원본 구조와 여러 쪽 별지를 시각 확인했다. 단순 파서 테스트 통과만으로 호환성을 판정하지 않는다.

```sh
cd capacitor-web
npm ci
npm run build
npm test
DARI_HWP_FIXTURE=/tmp/dari-review.hwp node --experimental-strip-types --test tests/application-hwp.test.mjs
# 전체 작성 완료 상태의 가상 메타데이터 → 14번 답변 → HWP/PDF 출력 예시:
DARI_FULL_EXPORT_DIR=/tmp/dari-full-demo node --experimental-strip-types --test tests/export-full-fixture.test.mjs
```

전체 예시는 `tests/export-full-fixture.mjs`에서 직접 작성한 가상 정보다. 러시아 국적 개발자 Aleksei Sokolov를 설정하고 가족·학력·경력·상트페테르부르크에서 사마라로의 피신·이스탄불 환승·한국 입국의 시간 흐름을 맞췄다. 학교와 직장은 가공 기관이며 상세 주소와 연락처는 시연용으로 생략하거나 무효값을 사용한다. 실제 인물이나 사건의 재현 또는 실제 LLM 실행 결과가 아니다. 161개 메타데이터 항목과 영어 원문, 한국어 초안을 준비하고 실제 `buildQuestion14Answers` 및 출력 경로를 사용한다. 서명·동의 영역은 비워두고 적용되는 89개 출력 항목의 미작성 여부, 체크 기호, 표 셀 정렬을 검사한다. JSON에도 가상 예시라는 표시를 포함한다.

15번 자유서술은 일반 본문 줄 간격을 사용하지 않는다. `src/export/statement.ts`에 원본의 19쪽 8개 행과 20쪽 22개 행을 매핑했다. PDF는 각 밑줄 위 2pt에 기준선을 놓으며 HWP는 원본 표의 한 행에 한 줄씩 아래 정렬과 2pt 여백을 적용한다. 전체 행 수를 넘으면 내용을 자르지 않고 번호 별지로 보낸다.

개발 서버의 `/tests/export-qa.html`에서는 모델 추론 없이 가상 답변으로 생성 버튼을 시험할 수 있다. 실제 신청자 세션에 예시를 주입하지 않으며 배포 빌드에 테스트 페이지를 넣지 않는다.

## 후속 확인

- Windows 한글, 한컴독스, 모바일 HWP 뷰어 및 네이티브 파일 저장/공유 동작은 추가 확인한다.
- 설치된 글꼴과 뷰어의 조판 차이로 줄바꿈이 달라질 수 있으므로 내려받은 HWP를 열어 페이지 나눔과 빈칸, 별지를 최종 검토한다.
- 2019년 양식을 다른 개정본으로 바꾸려면 HWP/PDF 템플릿과 표 행, 선택지 라벨, 모든 문항 매핑, 버전 안내 및 테스트를 함께 갱신해야 한다.
